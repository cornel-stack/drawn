# Fact-check — LA-03

Source: Jim Hefferon, *Linear Algebra* (CC BY-SA 3.0), §1.III Reduced Echelon
Form. Local extract:
`sources/text/hefferon-linear-algebra/003-reduced-echelon-form.md`. Our lesson
explains the material in its own words; both worked systems and the s2 drive use
our own numbers (not Hefferon's). Line numbers below are into that extract.

## s2 — echelon to reduced echelon form (`rrefDef`, the drive)

**Definition of reduced echelon form (`rrefDef`).** The narration ("each
leading entry is a 1, and it must be the only non-zero number in its whole
column") is Definition 1.3 verbatim in substance:

> "A matrix or linear system is in reduced echelon form if, in addition to being
> in echelon form, each leading entry is a 1 and is the only nonzero entry in its
> column." — §1.III.1, Def 1.3, p. 51, lines 208-210

**Gauss-Jordan / pivoting (the two extra stages).** The lesson's two stages
(make leading entries 1, then clear upwards) are Hefferon's:

> "We can keep going to a second stage by making the leading entries into 1's
> ... and then to a third stage that uses the leading entries to eliminate all of
> the other entries in each column by combining upwards." — §1.III.1, Example
> 1.1, p. 50-51, lines 93, 117-118

> "Using one entry to clear out the rest of a column is pivoting on that entry.
> ... the combination operations in the third stage move right to left." —
> §1.III.1, p. 51, lines 161-163

> "This extension of Gauss's Method is the Gauss-Jordan Method or Gauss-Jordan
> reduction." — §1.III.1, Example 1.2 close, p. 51, lines 206-207

**The drive itself — our own echelon matrix, verified in numpy.** The animation
starts from echelon `[[1,2,-1,-1],[0,1,3,5],[0,0,2,4]]` and performs
`(1/2)R3`, then `R2-=3R3` and `R1+=R3`, then `R1-=2R2`:

```python
import numpy as np
M = np.array([[1,2,-1,-1],[0,1,3,5],[0,0,2,4]], dtype=float)
M[2] *= 0.5                      # (1/2)R3
M[1] += -3*M[2]; M[0] += 1*M[2]  # clear z column above the pivot
M[0] += -2*M[1]                  # clear y in top row
print(M)
print("cross-check solve:",
      np.linalg.solve([[1,2,-1],[0,1,3],[0,0,2]], [-1,5,4]))
```

output:
```
[[ 1.  0.  0.  3.]
 [ 0.  1.  0. -1.]
 [ 0.  0.  1.  2.]]
cross-check solve: [ 3. -1.  2.]
```

The RREF is exactly `[[1,0,0,3],[0,1,0,-1],[0,0,1,2]]`, and the constants column
`(3, -1, 2)` equals `np.linalg.solve` on the echelon coefficient block.
**Confirmed.**

## s3 — reading off / rank / free variable / uniqueness (`soln`, `rankEq`, `freeSol`, `vecForm`)

**Read the solution straight off (`soln`).** The point of the extra arithmetic:

> "The benefit is that we can just read off the solution set description." —
> §1.III.1, p. 51, lines 211-212

> "Example 1.1 and 1.2 show how in a single element solution set case the single
> element is in the column of constants." — §1.III.1, p. 51-52, lines 224-225

`soln` is `x=3, y=-1, z=2` — exactly the constants column of the s2 RREF above.
**ok.**

**Zero row = redundant equation; column with no leading entry = free variable
(`freeSol`).** Hefferon:

> "in an echelon form matrix any column that does not contain a leading entry is
> associated with a free variable." — §1.III.2, p. 60, lines 955-956

> "This system x+y=1, y+z=2 has one free variable, z, because it is the only
> variable not leading a row. We have the habit of parametrizing using the free
> variable ... x = -1+z" — §1.III.2, p. 60, lines 969-974

`freeSol` (`x=5-2z, y=3+z, z free`) is this form with our own numbers; verified
in the s5 block.

**Vector / parametric form (`vecForm`).** Example 1.4's solution set is a fixed
column plus a scalar multiple of a direction column:

> "S = { (x1,x2,x3,x4) = (-9/2, 3, 0, -2) + (1/2, -1/3, 1, 0) x3 | x3 ∈ R }" —
> §1.III.1, Example 1.4, p. 52, lines 312-354

`vecForm` `(5,3,0) + z(-2,1,1)` is the same shape — one particular point plus a
line; components verified in s5.

**Rank (`rankEq`) — OUR terminology, flagged.** Hefferon's §1.III does *not* use
the word "rank" (it is introduced later, in Chapter Two). In §1.III he counts
"leading entries" and "nonzero rows". The lesson's claim `rank = #leading
entries = #nonzero rows` is grounded in:

> "In an echelon form matrix, no nonzero row is a linear combination of the other
> nonzero rows." — §1.III.2, Lemma 2.5, p. 56, lines 872-873

so each nonzero row is an independent constraint, and (Def 1.3 / echelon form)
each nonzero row has exactly one leading entry — hence #leading entries =
#nonzero rows. **The word "rank" is our pedagogical label layered on Hefferon's
counts; it is not his term in this section.** Flagged here per instruction; the
equation's content is sound. **ok.**

**Uniqueness of reduced echelon form.** The "whatever order you do the
operations in, the reduced echelon form is unique" claim is Theorem 2.6:

> "Each matrix is row equivalent to a unique reduced echelon form matrix." —
> §1.III.2, Theorem 2.6, p. 59, lines 909-910

and the free-variable invariance (Corollary 2.7, p. 60, lines 977-978):

> "If from a starting linear systems we derive by Gauss's Method two different
> echelon form systems, then the two have the same free variables."

The three-case classification (no / one / infinitely many solutions, now read
off directly) is §1.III.1, p. 51, lines 213-218 and §1.III.2, lines 1020-1022.
**All ok.**

## s4 — unique-solution worked problem (`given`, `step2`, `answer`, check)

Our own 3×3 system `x+y+z=4, 2x-y+z=0, x+2y-z=9` (`given`). Each RREF row reads
a single variable (`step2`), and the constants column is the boxed answer
(`answer`):

```python
import numpy as np
print("solve:", np.linalg.solve([[1,1,1],[2,-1,1],[1,2,-1]], [4,0,9]))
print("check expr:", np.linalg.solve([[1,1,1],[2,-1,1],[1,2,-1]], [4,0,9])[0])
```

output:
```
solve: [ 2.  3. -1.]
check expr: 2.0
```

The gate's `check.expr` returns `2.0`, matching declared `value: 2.0` (tol 1%).
Boxed answer `(2, 3, -1)` is exact. **Verdict: ok.**

## s5 — free-variable worked problem (`given2`, `answer2`, check)

Our own system `x+y+z=8, 2x-y+5z=7, 3x+6z=15` (`given2`). `R2-=2R1`, `R3-=3R1`
make rows two and three proportional, so `R3-=R2` leaves a zero row (redundant
equation); the RREF has leading ones in x and y but none in z, so z is free:

```python
import numpy as np
F = np.array([[1,1,1,8],[2,-1,5,7],[3,0,6,15]], dtype=float)
F[1] += -2*F[0]; F[2] += -3*F[0]
F[2] += -1*F[1]        # -> zero row
F[1] *= (-1/3); F[0] += -1*F[1]
print(F)
z = 1; x = 5 - 2*z; y = 3 + z
print("z=1 ->", (x, y, z))
print("eq1", x+y+z, "eq2", 2*x-y+5*z, "eq3", 3*x+6*z)
print("s5 check expr '5-2*1' =", 5 - 2*1)
```

output:
```
[[ 1.  0.  2.  5.]
 [-0.  1. -1.  3.]
 [ 0.  0.  0.  0.]]
z=1 -> (3, 4, 1)
eq1 8 eq2 7 eq3 15
s5 check expr '5-2*1' = 3
```

RREF is `[[1,0,2,5],[0,1,-1,3],[0,0,0,0]]`, giving `x = 5-2z, y = 3+z, z free`
(`answer2`). Setting `z=1` gives `(3, 4, 1)`, which satisfies all three original
equations (8, 7, 15). The gate's `check.expr` `5 - 2*1` returns `3`, matching
declared `value: 3.0` (tol 1%). **Verdict: ok.**
